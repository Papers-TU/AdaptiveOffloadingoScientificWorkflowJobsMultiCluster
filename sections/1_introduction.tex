Data-driven science has produced massive datasets from high-throughput instruments, large simulations, and sensor networks, whose analysis requires substantial computational effort. Scientific workflows are a key abstraction for structuring these computations~\cite{vivas_trends_2024} and are implemented by researchers using Scientific Workflow Management Systems (SWMSs) such as Snakemake~\cite{molder_sustainable_2021} for complex, reproducible analyses.

At scale, workflows comprise hundreds to thousands of jobs and run for hours to months~\cite{juve_characterizing_2013}. Especially long-running workflows can monopolize local infrastructures, as they require significant compute, storage, and networking resources, leading to contention among jobs and delayed results.

Given that research institutions can often access federated computing resources such as shared HPC or the cloud beyond their on-premises infrastructure, scientists should be able to bundle these resources for accelerated time-to-result while maintaining control over operational expenditures~\cite{wang_managing_2016, farahani_clusterless_2026, zhang_elastic_2024}. 
 \begin{comment}
Existing approaches address related settings: ClusterLess~\cite{farahani_clusterless_2026} orchestrates deadline-constrained serverless workflows across federated edge clusters, and ETHC~\cite{zhang_elastic_2024} offloads tasks from on-premises data centers to the public cloud under renting-cost constraints using online deep reinforcement learning. 

\end{comment}

Our proposed lightweight method satisfies this requirement using the architecture depicted in Fig.~\ref{fig:intro}. 
We assume a primary compute environment that serves as the default execution site, but may have limited resource capacity. 
A secondary environment is available that can provide additional resources when necessary. 

Based on a user-defined time-to-result, SOU predicts job runtimes from historical executions, computes the makespan across clusters by simulating the execution, and chooses jobs for offloading via a configurable job selection criterion until the target is met.
We contribute the Snakemake Offloading Utility (SOU), an offloading middleware implemented as an extension of Snakemake.\footnote{\url{https://github.com/dos-group/snakemake-offloader}}
